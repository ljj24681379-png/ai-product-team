# 一人 AI 产品团队

> 一个产品经理如何带着多个 Agent，从一个想法走到可运行 Demo。

**状态：第一版已完成 · 交互 Demo 可运行**

## 项目是什么

这是一个 AI 面试训练工具实验。用户输入目标岗位后，产品生成针对性面试问题，进行模拟问答与动态追问，并把回答转成结构化反馈和下一轮练习建议。

## 为什么做

大学生准备面试时，常遇到四类问题：题目来源零散、不知道回答质量、缺少连续追问、练习结果无法沉淀。单次生成题库不能形成训练闭环；真正需要的是“岗位理解—模拟面试—反馈—再次练习”的连续过程。

## 第一版为什么不够

第一版如果只做“输入岗位、生成问题”，本质仍是一个 Prompt 包装：

- 问题是否匹配岗位无法解释；
- 追问没有利用用户上一轮回答；
- 反馈容易停留在笼统评价；
- 练习记录不能形成能力变化线索。

## Agent 分工

| 角色 | 负责内容 | 交付物 | 验收重点 |
| --- | --- | --- | --- |
| 研究 Agent | 搜集岗位要求、题型和能力项 | 岗位能力卡 | 来源与岗位相关性 |
| 产品 Agent | 功能拆解、需求和验收标准 | MVP 任务单 | 范围与完成条件 |
| 设计 Agent | 页面结构、信息层级和交互 | 页面说明 | 任务链路是否清楚 |
| 开发 Agent | 前端与最小功能实现 | 可运行 Demo | 核心路径可用 |
| 测试 Agent | 用例、检查和问题反馈 | 缺陷清单 | 可复现与优先级 |

## 我自己的角色

我是产品负责人和最终决策者，负责定义目标、控制范围、选择方案、处理 Agent 之间的冲突并验收结果。Agent 可以提供候选方案和执行产物，但不替代产品取舍与发布责任。

## Demo

```text
输入目标岗位
  ↓
生成岗位能力卡与面试问题
  ↓
模拟面试与自动追问
  ↓
结构化回答反馈
  ↓
沉淀本轮记录并进入下一轮
```

第一版已覆盖一条完整训练路径：可以选择岗位、生成问题、输入回答、获得结构化反馈并进入下一轮追问。反馈由透明的静态规则驱动，不接入真实招聘平台，也不对用户是否能通过面试作承诺。

## 产品判断

多 Agent 协作的价值不是角色越多越好，而是让任务边界、交付物和检查关系更清晰。稳定步骤应该使用固定交接协议；研究和方案生成可以保留一定自主性；最终目标和发布判断必须由人承担。
